# Roadmap

This document separates verified current scope from product direction. Planned items are not commitments and should not be described as available until implemented and tested.

## Completed

### Playable seven-key foundation

- Three.js seven-lane highway and responsive camera framing.
- Original synthesized demo audio and authored demo chart.
- Audio-clock timing, tap/chord/hold judgment, score, accuracy, combo, misses, and results.
- Pause, resume, restart, seek/debug hooks, calibration, speed, and chart offset.
- Keyboard input using `A S D Space J K L`.

### Mobile input and layout

- Landscape-first framing and orientation overlay.
- Multi-touch chords and holds.
- Pointer ownership, cancellation safety, and lane-to-lane slide/swipe input.
- Fullscreen/orientation affordances and device-layout diagnostics.

### Local music workflow

- Local audio validation and browser decoding.
- Worker-based onset, tempo, beat-grid, energy, and section analysis with inline fallback.
- Deterministic chart generation and validation from that analysis.
- Role-aware lane placement and measured analysis diagnostics.
- IndexedDB storage of charts, metadata, diagnostics, high scores, and optional original/transcoded audio.
- Memory-only fallback when persistent browser storage is unavailable.

### Difficulty modes and weighted scoring

- Easy (4 keys, `A S K L`), Normal (5 keys, `A S SPACE K L`), and Hard (7 keys, `A S D SPACE J K L`) generated independently from a single analysis.
- Per-difficulty lane profiles, density/chord/hold budgets, and lane-count-aware rendering, camera framing, and touch columns.
- Difficulty selector after import with lane count, estimated notes, notes per second, score weight, and maximum theoretical score per chart.
- Difficulty switching during play without re-analysis or re-decoding.
- Weighted scoring (×1.0 / ×1.5 / ×2.0) with accuracy normalised independently of the multiplier.
- High scores stored separately per song and difficulty, versioned and recorded with their weight.
- Version-2 song records and in-place migration of seven-key records to Hard, with explicit regeneration for the missing difficulties.

### Difficulty rebalance, hold accuracy, and lane colours

- Hard restored to the phase 2.1 seven-key chart, reproduced note for note (same seed, same chord budget, no wider chords), verified against a chart generated by the v0.2.1 code.
- Easy and Normal rebalanced as genuinely simpler adaptations: lower density, wider minimum spacing, fewer chords and holds, and never a chord wider than the baseline's two notes.
- One shared hold-geometry function for the falling and held states, with the trail derived from the note's chart timestamps, clipped at the spawn plane instead of stretched, and aligned at every scroll speed and lane count.
- A three-colour lane language (colour 1 / colour 2 / orange for Space) with the exact pattern per difficulty, applied to notes, hold heads and trails, receptors, lane strips, the key strip and the touch pads, plus two persisted themes.
- Maximum score replaced with the reachable score of a flawless run, so the displayed percentage hits 100 % on a perfect play.

### Engineering baseline

- Strict TypeScript configuration.
- Automated unit, DSP fixture, DOM input, layout, import, generation, storage, and timing tests.
- Reproducible npm workspace lockfile and static Vite production build.

## Next milestone

- Chart regeneration controls per difficulty: re-roll the seed, compare densities, and replace one difficulty's chart without touching the others.

- Assisted timing correction for generated charts: nudge, delete, and add notes on a beat grid.
- Decide and test how mobile performance and readability hold up with four wide lanes versus seven narrow ones on real devices.

## Planned, not implemented

### Chart workflow

- Assisted chart editor and manual timing correction.
- Versioned chart import/export user interface.
- Regeneration controls for tempo, seed, density, and difficulty (including per-difficulty seeds).
- Local library management beyond the current stored-song workflow.

### Quality and accessibility

- Cross-browser end-to-end smoke automation.
- Device performance profiling and lower-power rendering options.
- Keyboard remapping, accessibility review, additional calibration guidance, and visual/audio feedback options.
- Production screenshot set, supported-browser matrix, and formal release checklist.

### Possible online service

- Public chart discovery, accounts, moderation, publishing, and score services.
- YouTube URLs as references through permitted official APIs, not as an audio extraction source.
- Server-side validation, authorization, rate limiting, reporting, and data retention policies.

An online service would be a separate architecture and security milestone. The current static application does not need Laravel, another backend framework, a server database, Docker, or CI/CD infrastructure.

## Decisions still required

- Select a project software license before public redistribution or outside contributions.
- Establish a browser/device support policy and performance floor.
- Decide whether production source maps should be public.
- Define backup/export expectations for browser-local libraries before storage schema changes.
- Establish music and chart-content rights rules before any sharing feature is designed.
